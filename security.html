Wi-Fi Security
WPA3-Personal（SAE）與 Enhanced Open（OWE）

WPA3-Personal 用 SAE（Simultaneous Authentication of Equals）取代 WPA2 的 PSK：密碼不再直接衍生 PMK，而是透過一次以橢圓曲線為基礎的密碼認證金鑰交換（PAKE）得到每次連線都不同的 PMK。本頁依 IEEE 802.11-2024 §12.4 與 Wi-Fi Alliance WPA3 Specification v4.0 整理 SAE 的訊框、金鑰推導、狀態機，以及 WPA3 在 Wi-Fi 6E / 7 / 8 上的限制。

1總覽

WPA3 是 Wi-Fi Alliance 的認證計畫，底層機制來自 IEEE 802.11。WPA3 Spec v4.0 定義三個家族：WPA3-Personal（密碼，SAE）、WPA3-Enterprise（802.1X / EAP，含 192-bit 模式）、Wi-Fi Enhanced Open（OWE，無密碼但加密）。本頁目前涵蓋 WPA3-Personal（1–9）與 Enhanced Open（10）。

2為什麼要 SAE：PSK 的根本問題

WPA2-Personal 的 PMK 直接由密碼算出（PBKDF2(passphrase, SSID)），4-way handshake 的 MIC 又是用這把 PMK 算的。攻擊者只要錄下一次 4-way handshake，就能離線無限次猜密碼。

性質WPA2-PSKWPA3 SAE
PMK 來源PMK = PBKDF2(密碼, SSID)，固定不變每次 SAE 交換都產生新的 PMK（雙方隨機數參與）
離線字典攻擊錄下 4-way handshake（或 PMKID）即可離線暴力猜不可行：每次主動攻擊只能驗證一個密碼猜測
前向保密無：知道密碼即可解開過去錄下的所有流量有：日後密碼外洩也推不出過去的 PMK
知道密碼的旁觀者可被動解密其他人的流量不行：每個 STA 的 PMK 由各自的 DH 交換決定
角色Supplicant / Authenticator「對等」：雙方都可主動發起（源自 mesh 需求）
冒充 AP（evil twin）知道密碼就能架假 AP仍可能（密碼是對稱秘密）→ 需要 SAE-PK

802.11-2024 §12.4.1（PDF p.2961–2962）列出 SAE 的安全性質：被動觀察或中繼都無法得到密碼或 PMK；修改、偽造、重放訊框也無法得到；每次攻擊最多只能猜一個密碼；舊 PMK 外洩不影響其他次交換；密碼外洩也推不出先前的 PMK。SAE 是 Dragonfly（IETF RFC 7664）的變形。

3連線全貌：從 Beacon 到加密資料

SAE 只取代「認證」這一步。它產生 PMK 之後，後面的 Association 與 4-way handshake 和 WPA2 的流程一樣。

SAE 階段
在 802.11 Authentication frame 中完成（Authentication Algorithm Number = 3）。只產生 PMK，還沒有加密金鑰。
Association
STA 在 RSNE 中選定一組 RSN 參數（一個 AKM、一個 pairwise cipher、PMF 等），AP 檢查是否與自己宣告的相容。
4-way handshake
由 PMK + 兩個 nonce 推出 PTK（KCK / KEK / TK），並下發 group key。M3 回顯 Beacon 中的 RSNE / RSNXE，讓 STA 偵測降級攻擊。
PMKSA caching：SAE 完成後的 PMK 會以 PMKID 識別並快取。下次重新連同一台 AP 時，STA 在 (Re)Association Request 的 RSNE 帶上 PMKID，AP 若找得到就跳過 SAE 直接做 4-way handshake，省下大量運算。

4SAE 協定細節

SAE 包含兩組交換：Commit 交換迫使雙方各自「承諾」一個密碼猜測，Confirm 交換證明猜測正確（§12.4.5，PDF p.2971–2975）。以下以橢圓曲線（ECC）群組說明。

4.2 產生密碼元素 PWE：Hunting-and-Pecking vs Hash-to-Element

4.3 Commit：每一方要做什麼

  1. 產生兩個一次性亂數 rand、mask（1 < 值 < r，且 (rand+mask) mod r > 1；不可在不同次交換重用）。
  2. 計算 commit-scalar = (rand + mask) mod r、COMMIT-ELEMENT = −(mask · PWE)，之後 mask 可丟棄。
  3. 以 Authentication frame 送出（Algorithm = 3、Transaction Seq = 1）：Finite Cyclic Group、Scalar、Element。依情況再附上：
    • AKM Suite Selector element：要使用 AKM 24 / 25 時必須帶上，對方回應時須帶相同 AKM，否則認證失敗（防止 AKM 被竄改）。
    • Password Identifier element：同一 SSID 有多組密碼時，用來指定是哪一組。
    • Rejected Groups element：H2E 下，列出先前被對方拒絕的群組；這份清單會被納入 KDF 的 salt，防止群組降級攻擊。
    • Anti-Clogging Token：對方要求時才附上（見 4.6）。

4.4 收到對方 Commit：驗證與算出 PMK

  1. 驗證 scalar：必須 1 < scalar < r。驗證 element：座標在 [0, p) 且是曲線上的點、不是無窮遠點。若對方送來的 scalar 或 element 與自己送出的相同，也判失敗（防反射攻擊）。
  2. 計算共同秘密：K = rand · (peer-scalar · PWE + PEER-ELEMENT)。K 若為單位元素則拒絕；否則取 k = F(K)（ECC 為 x 座標）。
  3. keyseed = H(salt, k)：salt 平時為全 0；H2E 且有被拒群組時，salt 為雙方 Rejected Groups 串接（MAC 較大者在前）。
  4. context = (commit-scalar + peer-commit-scalar) mod r，以 KDF(keyseed, "SAE KCK and PMK", context) 切出 SAE-KCK 與 PMK；PMKID = context 的前 128 bits。
為什麼離線字典攻擊行不通：scalar / element 被 rand 與 mask 遮蔽，旁觀者看到的只是隨機的群組元素；要驗證一個密碼猜測，攻擊者必須用該猜測產生的 PWE 參與一次真實的交換，每次交換只能試一個密碼。

4.5 Confirm：證明雙方算出同一把金鑰

  • confirm = CN(SAE-KCK, send-confirm, 己方 scalar, 己方 element, 對方 scalar, 對方 element)，CN 是 HMAC 形式的雜湊。
  • 送出 Authentication frame（Seq = 2、Status = 0），內含 Send-Confirm 計數器（防重放，每次重送遞增）與 Confirm 欄位。
  • 收方以相反順序（對方的放前面）計算 verifier 比對；不符則以 Status 15（CHALLENGE_FAILURE）拒絕。雙方都驗證成功即完成認證，PMK 交給後續 Association 與 4-way handshake 使用。

4.6 Anti-Clogging：防止 Commit 洪水

處理一個 Commit 需要數次橢圓曲線純量乘法，攻擊者可以偽造大量 MAC 送 Commit 把 AP 的 CPU 耗光。對策（§12.4.6，PDF p.2975–2976）：

  • AP 的 SAE 父程序維護計數器 Open（處於 Committed / Confirmed 的協定實例數）。超過 dot11RSNASAEAntiCloggingThreshold 後，對每個新 Commit 不做運算，直接以 Status 76 回覆一個與來源 MAC 綁定的 token（例如 H(秘密, MAC)），AP 自己不需要保存狀態。
  • STA 必須把 token 原封不動附在下一個 Commit 中重送，證明自己真的能在那個 MAC 位址收到訊框。H2E 下 token 包在 Anti-Clogging Token Container element 中。

6AKM 與金鑰長度

同樣是 SAE，AKM 不同會影響 PMK 長度、後續 KDF 的雜湊與是否支援 FT。Wi-Fi 7 以上必須使用 AKM 24（GDH = Group-Dependent Hash）。

6.1 STA 的 AKM 選擇順序（WPA3 Spec §5.4.1）

當 AP 同時宣告多個 AKM，WPA3 STA 必須依下列順序選第一個雙方都允許的：

  1. EPPKE（base AKM 25，FT-SAE-GDH）— security profile #2
  2. FT over SAE-GDH（:25）
  3. EPPKE（base AKM 24，SAE-GDH）— security profile #1
  4. SAE-GDH（:24）— security profile #9
  5. FT over SAE（:9）
  6. SAE（:8）
  7. FT over PSK（:4）
  8. PSK SHA-256（:6）
  9. PSK（:2）
這個順序只規範「在同一個 BSS 內選哪個 AKM」，不代表 STA 在多台 AP 之間如何挑選。

7.1 所有 WPA3-Personal 模式共通要求（WPA3 Spec §2.5）

AP 端
  • 同一 BSS 不得同時開 WPA1、WEP、TKIP。
  • 開了任何 PSK AKM，就必須同時開 SAE（除非管理者明確設為 WPA2-Personal Only）。
  • 啟用 EHT / MLO：必須開 AKM :24 與 pairwise GCMP-256。
  • 啟用 UHR：必須開 security profile #1（EPPKE + SAE :24）與 #9（SAE :24）。
  • SAE 只能使用 DH 群組 15–21。
STA 端
  • 依 6.1 的 AKM 順序選擇；Network Profile 不得開 WEP / TKIP。
  • 啟用 EHT / MLO：Network Profile 必須允許 :24 與 GCMP-256。
  • 啟用 UHR：至少允許 security profile #1 或 #9。
  • H&P 迴圈 k ≥ 40；實作須避免可經 cache 觀察的執行差異。
RSN overriding 的降級防護：支援 overriding 的 STA 會把 SNonce 最後 6 octets 設為特定 cookie；AP 在 M2 看到 cookie，就在 M3 把 Beacon 中所有 RSNE / RSNXE 變體（含 Override 版本）完整回顯，STA 比對不一致即中斷連線。M2 若帶 RSN Selection element，也必須與 Association Request 中的一致（WPA3 Spec §15.3）。

8Transition Disable：關掉降級的後門

Transition 模式的風險：攻擊者架一個只宣告 PSK 的假 AP，誘使支援 WPA3 的 STA 改用 PSK 連線，再錄下 4-way handshake 做離線字典攻擊（Dragonblood 的降級攻擊）。Transition Disable 讓 AP 通知 STA：「這個網路已全面支援 WPA3，以後別再用舊方法。」

AP

如何指示

在 4-way handshake 的 M3 Key Data 中放 Transition Disable KDE（WFA OUI 50-6F-9A、type 0x20），因此受 PTK 保護、無法偽造。FILS 時放在 (Re)Association Response 的 Key Delivery element。只對 WPA3 / Enhanced Open 關聯送出，不送給 WPA2 關聯；AP 預設不得啟用，須由了解全網設定的管理者或 controller 決定。

STA

收到後怎麼做

該 SSID 的 Network Profile 永久停用 WEP / TKIP 與「不協商 PMF 的連線」，並依 bitmap 停用對應的舊演算法，套用到該 SSID 的所有 BSS，直到 profile 被刪除。實作可要求使用者確認。

9SAE-PK：密碼公開也不怕假 AP

咖啡廳、旅館的密碼貼在牆上，任何人都知道。一般 SAE 可防竊聽，但無法防止知道密碼的人架設假 AP（evil twin）。SAE-PK 讓 AP 額外持有一組 ECDSA 金鑰，密碼本身就是 AP 公鑰的指紋（WPA3 Spec §7）。

9.1 密碼怎麼來

  • 管理者產生金鑰對 K_AP / k_AP（至少支援 P-256），全網所有 AP 共用同一組，私鑰不得離開 AP。
  • 一次性暴力搜尋 128-bit Modifier M，使 Hash(SSID ‖ M ‖ K_AP) 的前 Sec octets 為 0（Sec = 3 或 5）。這種 hash extension 讓較短的密碼也有足夠的抗第二原像強度。
  • 其餘指紋位元以 Base32 編碼，每 4 字元加一個連字號，最後一個字元是 Verhoeff 檢查碼，例如 a2bc-de3f-ghi4。密碼至少 12 字元。

9.2 連線時多做的事

  1. STA 在 SAE Commit 以 Status 127（SAE_PK）表示要用 SAE-PK（隱含 H2E）；AP 在 RSNXE 設 SAE-PK 位元宣告支援。
  2. SAE 的 KDF 額外切出一把 KEK（標籤 "SAE-PK keys"）。
  3. AP 的 SAE Confirm frame 額外夾帶：以 KEK 加密（AES-SIV）的 Modifier、FILS Public Key element（K_AP）、FILS Key Confirmation element（對雙方 element、scalar、M、K_AP 與雙方 MAC 的 ECDSA 簽章；MLD 之間使用 MLD MAC 位址）。
  4. STA 解出 M，由 SSID + M + K_AP 重算指紋並與密碼比對（或與先前儲存的公鑰比對），再驗證簽章。全部成功才進入 Accepted，並儲存公鑰供下次使用。

部署提醒：安全要求較高的網路建議 S ≥ 92 bits。SAE-PK 只防假 AP，不防「知道密碼的人連進來」，仍需搭配 client isolation。AP 預設應在 SAE-PK 連線中送出 Transition Disable bit 1，否則 STA 仍可能被降級到一般 SAE。

10Wi-Fi Enhanced Open（OWE）

咖啡廳、機場的開放網路傳統上完全不加密，同一個熱點的任何人都能側錄別人的流量。OWE（Opportunistic Wireless Encryption）在 association 時順便做一次未認證的 Diffie-Hellman 交換，讓每個 STA 都有自己的金鑰。使用者體驗和開放網路一樣，不需要輸入密碼。Wi-Fi Alliance 的認證名稱是 Wi-Fi CERTIFIED Enhanced Open，底層定義在 802.11-2024 §12.14（PDF p.3128–3130），源自 IETF RFC 8110。

做到的事
防止被動竊聽：每個 STA 的 PMK 都來自獨立的 DH 交換，旁觀者無法解密，連上同一熱點的其他人也不行。
做不到的事
沒有認證：STA 無法確認 AP 是真的，假 AP 可以完整扮演中間人。存取控制要靠其他機制（例如 captive portal）。
代價
只在 association 中多一個 DH element，沒有額外的認證交換；STA 與 AP 各做一次純量乘法與一次共同秘密運算。

10.1 連線流程

10.2 金鑰推導（§12.14.2）

  1. STA：選一個群組，隨機產生私鑰 m（1 < m < r），算公鑰 C = m · G，放進 DH Parameter element（Group + Public Key）。想用 PMKSA caching 時，同時在 RSNE 帶 PMKID。
  2. AP：若 PMKID 對得到快取的 PMKSA，就忽略 DH 參數，直接進 4-way handshake。否則檢查群組（不接受就以 UNSUPPORTED_FINITE_CYCLIC_GROUP 拒絕 association），並用 SAE 的 element 驗證規則檢查 C（失敗以 REQUEST_DECLINED 拒絕）。
  3. AP：產生私鑰 n、公鑰 A = n · G，計算：
    • S = n · C、s = F(S)（取 x 座標）
    • prk = HKDF-Extract(C ‖ A ‖ group, s)
    • PMK = HKDF-Expand(prk, "OWE Key Generation", 雜湊長度)
    • PMKID = Truncate-128(Hash(C ‖ A))
    雜湊依群組選擇（Table 12-1）：19 → SHA-256、20 → SHA-384、21 → SHA-512。S、s 用完立即刪除。
  4. STA：確認回應中的 Group 與自己送出的相同、驗證 A，再以 S = m · A 算出同一組 PMK / PMKID。
群組協商：AP 拒絕群組時，STA 可以換一個群組重新 association。WFA 的 OWE 規範要求群組 19（P-256）必須支援，20、21 為選用。與 SAE 不同，OWE 的群組選擇沒有像 Rejected Groups 那樣的降級保護，但因為本來就不認證，影響有限。

10.4 Transition Mode：讓舊裝置也連得上

舊 STA 看不懂 AKM 18，不能連 OWE BSS。Enhanced Open Transition Mode 的做法是同時架兩個 BSS（WPA3 Spec §4.3，細節定義在 WFA OWE Specification §2.2）：

  • OWE STA 在 Transition Mode 下會優先連 OWE BSS。只有在 AP 沒有提供 OWE 時，才退回傳統 Open（STA 的 Network Profile 處於 Transition 模式）。
  • 降級風險：攻擊者可以架一個沒有 Transition element 的 Open BSS。收到 Transition Disable bit 3 的 STA 可以（非必須）停用不加密的 Open。WPA3 Spec 特別提醒：由於 OWE 連線本身未經認證，攻擊者也可能利用這個機制讓 STA 連不上真正的 Open 網路（DoS）。
  • 不允許 Transition Mode 的情境：6 GHz、Sub-1 GHz，以及啟用 EHT / MLO 的 BSS（WPA3 Spec §4.3、§12）。這些情境下不加密的 Open 也被禁止，「開放網路」只剩 OWE 一種選擇。

11頻段與世代限制

新頻段與新世代沒有舊裝置包袱，所以 WPA3 Spec §12 直接禁止舊演算法。

情境禁止 / 要求
6 GHz（Wi-Fi 6E 以上）禁 TKIP、任何 PSK / FT-PSK、802.1X SHA-1、SAE Hunting-and-Pecking（只能 H2E）、Open 不加密、Transition 模式；PMF 必須 Required
Sub-1 GHz與 6 GHz 類似：禁 TKIP、PSK、H&P、Transition 模式；PMF Required
EHT / MLO（Wi-Fi 7）協商 EHT 或 MLO 的關聯不得使用 PSK 或 802.1X SHA-1；SAE 要用 :24（不用 :8）；pairwise 須支援 GCMP-256。AP 仍可為非 EHT 的舊 STA 宣告 PSK，舊 STA 會以 HE 以下的能力連線
UHR（Wi-Fi 8）一律以 Security Profile element 協商（取代 RSNE 選擇）；不可協商 profile #10–#15；在 SMD（Seamless Mobility Domain） 中只能使用 EPP 類 profile（#0–#7），因此 SAE 會以 EPPKE 形式出現

10.1 Wi-Fi 8 的 Security Profile

Security Profile element 把「AKM + cipher + 其他參數」打包成固定編號的 profile，減少組合數，也避免舊 STA 解析 RSNE 擴充欄位時出錯（WPA3 Spec §5.3、§16；細節定義在 802.11bn Draft）。與 SAE 相關的 profile：

Profile內容備註
#0Unauthenticated EPPKE（無 base AKM）Enhanced Open 的 Wi-Fi 8 版本
#1EPPKE + SAE :24UHR AP 必須啟用；可用於 SMD
#2EPPKE + FT-SAE :25Personal 選擇順序第一
#9SAE :24UHR AP 必須啟用；不可用於 SMD 關聯
UHR 部分引用 IEEE P802.11bn/D2.0，會隨 Draft 變動。AP MLD 的所有 affiliated AP 必須宣告相同的 Security Profile element；AP 在 M3 回顯該 element，STA 比對與 Beacon 不符就必須斷線。

10.2 MLD（Wi-Fi 7）上的 SAE

  • SAE 在 non-AP MLD 與 AP MLD 之間執行一次，雙方以 MLD MAC 位址作為身分（802.11be §12.4.1，PDF p.396；PWE、SAE-PK 簽章都使用 MLD MAC）。完成後一個 PMKSA / PTKSA 涵蓋所有 link。
  • (Re)Association Request 的 A1 / A2 必須與最後一次成功認證的 Authentication frame 相同（WPA3 Spec §11）。若預先認證的那條 link 消失，可透過任一 affiliated AP 以 PMKSA caching 重新認證。

11.1 系統設計檢查

AP / Router
  • 6 GHz 與 EHT BSS：預設 WPA3-Personal Only、H2E、AKM :24 + GCMP-256。
  • 2.4 / 5 GHz：評估 Transition 與 Compatibility 模式，對舊 STA 做相容性測試。
  • SAE 運算量：大量 STA 同時重連（開機、斷電恢復）時的 CPU 峰值與 anti-clogging 門檻。
  • Transition Disable 預設關閉，由 controller 依全網設定決定。
  • 多 AP 網路的 SAE-PK 私鑰與 Modifier 安全分發（規範未定義）。
STA / Client
  • 密碼以 UTF-8 + RFC 8265 OpaqueString 正規化，確保雙方得到相同的位元串。
  • PT 在設定密碼時預先算好（每個群組一份），縮短連線時間。
  • 保存 Transition Disable 狀態與 SAE-PK 公鑰，生命週期跟 Network Profile 綁定。
  • PMKSA caching 與 MAC 隨機化策略的取捨。
  • OCV（Operating Channel Validation）必須在 PMF 啟用時才使用（WPA3 Spec §13）。

13名詞表

SAE
Simultaneous Authentication of Equals，基於 Dragonfly 的密碼認證金鑰交換，雙方地位對等。
PAKE
Password-Authenticated Key Exchange，以密碼認證並協商金鑰，可抵抗離線字典攻擊。
AKM
Authentication and Key Management suite，例如 00-0F-AC:8（SAE）。
PWE
Password Element，由密碼與雙方 MAC 映射出的群組秘密元素。
PT
H2E 中只由密碼、SSID（與 Password ID）算出的中間秘密元素，可離線預算。
H2E
Hash-to-Element，確定性、可常數時間的 PWE 產生法（SSWU），取代 Hunting-and-Pecking。
H&P
Hunting-and-Pecking，以迴圈嘗試找出 PWE 的舊方法，有旁通道風險。
Scalar / Element
SAE Commit 中送出的純量與群組元素，由 rand、mask 與 PWE 算出。
SAE-KCK
SAE 的金鑰確認金鑰，用來計算 Confirm；與 4-way handshake 的 KCK 無關。
PMK / PMKID
Pairwise Master Key 與其識別碼；SAE 的 PMKID 取自雙方 scalar 和的前 128 bits。
PTK
Pairwise Transient Key，4-way handshake 由 PMK 推出，含 KCK、KEK、TK。
GDH
Group-Dependent Hash，AKM 24 / 25：KDF 雜湊依 DH 群組強度選擇。
PMF
Protected Management Frames（802.11w），MFPC = 能力、MFPR = 必須。
RSNE / RSNXE
RSN element / RSN Extension element，宣告 AKM、cipher、PMF 與 H2E、SAE-PK 等擴充能力。
RSN overriding
把較新的 RSN 參數放在 RSNE Override / Override 2 element，避免舊 STA 解析問題。
Anti-Clogging Token
AP 忙碌時要求 STA 回帶的無狀態 token，證明 STA 真的在該 MAC 上。
Transition Disable
AP 在 M3 以 KDE 通知 STA 永久停用某些舊演算法，防止降級。
SAE-PK
SAE Public Key：密碼即 AP 公鑰指紋，AP 以簽章證明身分，防 evil twin。
OWE
Opportunistic Wireless Encryption（AKM 18），在 association 時做未認證的 DH 交換，讓開放網路也能加密；WFA 認證名稱為 Enhanced Open。
DH Parameter element
Diffie-Hellman Parameter element（9.4.2.312），OWE 在 (Re)Association frame 中攜帶 Group 與公鑰。
OWE Transition Mode
公開的 Open BSS 與隱藏的 OWE BSS 以 vendor-specific element 互相指向，讓舊 STA 與 OWE STA 共用同一個網路名稱。
EPPKE
Enhanced Privacy Protection Key Exchange（802.11bi），Wi-Fi 8 的 security profile 使用。
Security Profile
Wi-Fi 8 以編號 profile 打包安全參數的機制，UHR 關聯一律使用。
OCV
Operating Channel Validation，在金鑰交換中確認雙方所在通道，防通道型中間人攻擊。

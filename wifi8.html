Wi-Fi 8（IEEE 802.11bn, UHR）
系統設計工程師導讀

Wi-Fi 8 的主軸不是更高的峰值速率，而是 Ultra High Reliability：在真實干擾、移動與多 AP 環境下，讓吞吐、延遲尾端與掉包率都更可預期。本頁整理標準目標、PHY/MAC 新機制，以及它們對 SoC、RF、韌體與系統架構的影響。

TGbn Task GroupUHR = Ultra High Reliability 2.4 / 5 / 6 GHz與 802.11be 向下相容內容更新至 2026-11
閱讀提醒：802.11bn 仍在 Draft 階段，各功能的細節（欄位格式、是否為 mandatory、參數值）會隨 Draft 版本變動。本頁著重於「概念與系統影響」，實作時請以 IEEE 802.11 Mentor 上最新 Draft 與 Wi-Fi Alliance 認證規範為準。

1一頁總覽

如果只記五件事：

① 從「快」轉向「穩」
維持 Wi-Fi 7 的 320 MHz、4096-QAM 與 MLO 骨架，KPI 改為「在相同 SINR 下的有效吞吐」、「95th 百分位延遲」與「MPDU 掉包率」。
② AP 之間開始合作
Multi-AP Coordination（Co-SR、Co-BF、Co-TDMA、Co-RTWT）讓鄰近 AP 協調時間、功率與空間，降低 OBSS 干擾。
③ 更聰明地使用頻寬
NPCA（主通道忙時改用非主通道）、DSO（動態子頻帶）、DRU（分散式 RU）提升寬頻道的實際利用率。
④ 漫遊不掉包
Seamless Mobility Domain 讓 STA 在 AP 之間轉移時不需重新 association / 重新建立 key，目標是零掉包的 BSS 轉換。
⑤ PHY 細修提升鏈路餘裕
新增中間 MCS、Unequal Modulation (UEQM)、更長 LDPC codeword、ELR 長距離模式，讓 link adaptation 更細緻。
⑥ 省電與共存
AP 端省電（AP Power Save）、更彈性的 STA 省電、In-Device Coexistence（與 BT/UWB/蜂巢共存）訊令。

2標準時程

IEEE 標準與 Wi-Fi Alliance 認證是兩條並行的時間線；晶片廠通常在 Draft 2.x 左右就會推出「Draft-compliant」產品。

3設計目標與 KPI

TGbn PAR 定義的目標相對於 802.11be，量測條件為「相同訊號 / 干擾環境」，而不是理想實驗室條件。

4PHY 層新功能

PHY 改動相對保守，目的是讓 link adaptation 更細、在邊緣訊號下更堅韌，並保留與 EHT 共用的硬體架構。

MCS

新增中間 MCS

在既有 MCS 之間插入新的調變 / 碼率組合，縮小相鄰 MCS 的 SNR 間距（原本約 2–3 dB），減少 rate adaptation 時「上一階太激進、下一階太保守」的損失。

系統影響：Rate control 演算法表格擴充；PER-vs-SNR 校準點增加；需要更準確的 SNR / EVM 估測。
MIMO

Unequal Modulation (UEQM)

不同 spatial stream 可使用不同調變階數。在通道矩陣奇異值差異大時（例如第 2 條 stream 明顯較弱），避免為了遷就最弱的 stream 而全體降階。

系統影響：Beamforming 回饋需要能支持 per-stream 決策；MIMO detector 與 bit-interleaver / parser 需支援混合星座。
FEC

2× LDPC codeword

新增約兩倍長度（3888-bit）的 LDPC codeword，可帶來約 0.5–1 dB 的編碼增益，尤其對大 A-MPDU 有利。

系統影響：LDPC decoder 面積 / 記憶體與延遲上升；需評估吞吐量模式下的 decoder 平行度與功耗。
UL / 6 GHz

Distributed RU (DRU)

把一個 RU 的 tone 分散到更寬的頻寬上。在 6 GHz LPI 有 PSD（功率頻譜密度）上限時，分散 tone 可讓 STA 以更高總功率上傳，改善上行覆蓋。

系統影響：AP 端排程器需支援 DRU 分配；STA PA 的 back-off 與法規 PSD 計算方式改變。
Range

Enhanced Long Range (ELR)

新的長距離 PPDU 格式，以較低速率換取更好的接收靈敏度，適合 IoT、戶外或邊緣覆蓋，用於提升管理 / 低速資料的可靠度。

系統影響：Preamble 偵測與 AGC 設計；與既有 ER SU 格式的辨識。
Preamble

UHR PPDU 格式

新增 UHR-SIG 等欄位以承載新功能訊令，同時保留 L-STF/L-LTF/L-SIG/U-SIG 讓舊裝置可正確 defer。

系統影響：基頻 RX 解析鏈需支援 HE / EHT / UHR 自動辨識；Wi-Fi 7 硬體多數可沿用。

5MAC 層新功能

Wi-Fi 8 的「可靠度」大多來自 MAC：更好的通道接入、排程、共存與省電。

6.1 NPCA — Non-Primary Channel Access

傳統 Wi-Fi 只要 主通道（primary 20 MHz）被 OBSS 佔用，整個寬頻道都必須等待，即使其他 sub-channel 是空的。NPCA 允許 AP/STA 在主通道忙碌時，切到預先協商的 NPCA primary channel 繼續競爭與傳輸。

系統影響：RF / 基頻需要快速切換 center frequency 與 primary（微秒級）；MAC 需正確追蹤 OBSS NAV 與 TXOP 結束時間；與 MLO、Preamble Puncturing 組合時的狀態機複雜度明顯上升。

6.2 其他 MAC 強化

頻寬

DSO – Dynamic Sub-band Operation

窄頻寬能力的 STA（例如只支援 80/160 MHz）可被動態分派到 320 MHz BSS 中的非主子頻帶，讓 AP 的寬頻寬被不同 STA 同時有效使用。

延遲

低延遲 / 優先接入

針對 latency-sensitive 流量的優先 EDCA 機制（如 P-EDCA）、更細的低延遲流量指示與排程資訊，搭配 Restricted TWT 保護時槽。

MLO

MLO / EMLSR 強化

縮短 EMLSR 鏈路切換延遲、改善 padding / transition 開銷，讓單 radio 的多鏈路裝置（手機常見）表現更接近 STR。

省電

AP Power Save

允許 AP（特別是電池供電的 Mobile AP / Mesh 節點）宣告不可用時段，STA 依此排程，減少 AP 的待機功耗。

共存

In-Device Coexistence (IDC)

標準化的訊令讓 STA 告知 AP 自己因 BT / LTE / 5G / UWB 共存而暫時不可用的時段，AP 避免在這些時間送資料，減少重傳。

可靠度

Link Adaptation 與 BA 強化

更即時的鏈路品質回饋、Block Ack 相關改良，提升重傳效率。HARQ 曾被提出討論，是否納入請追蹤 Draft 最新狀態。

6Multi-AP Coordination (MAPC)

Wi-Fi 8 最具結構性的改變：AP 之間有了標準化的協調協定。一個 Sharing AP 取得 TXOP 後，可邀請一個或多個 Shared AP 以協調方式使用同一段時間 / 頻率 / 空間。

模式協調維度運作方式需要的資訊實作難度
Co-TDMA時間Sharing AP 把 TXOP 的一段時間分給 Shared AP 使用，彼此不重疊。TXOP 時間、流量需求低
Co-RTWT時間（週期性）多 AP 對齊 Restricted TWT 服務時段，保護低延遲流量不被鄰 BSS 打斷。TWT 排程、低延遲流量需求低–中
Co-SR功率同時傳輸，但 Shared AP 依路徑損耗限制發射功率，使對方 STA 的 SINR 仍足夠。AP↔STA 的 RSSI / 路徑損耗、可容忍干擾中
Co-BF空間各 AP 對鄰 BSS 的 STA 做 null steering，同時同頻傳輸。跨 BSS 的 CSI（sounding 對鄰 STA）高
Joint Transmission空間（分散式 MIMO）多 AP 共同傳同一份資料，需相位同步與資料共享。精確時間 / 頻率 / 相位同步、高速 backhaul很高（未列為主要功能）
架構建議：先做 Co-TDMA / Co-RTWT（對 RF 要求低、主要是 MAC 排程），再做 Co-SR（需要跨 AP 的量測資料庫），最後 Co-BF（需要 sounding 與同步）。在 Mesh / EasyMesh 產品中，控制平面（controller）與 MAPC 的資料平面要分開設計。

7Seamless Roaming（Seamless Mobility Domain）

借用 MLO 的概念：把多個實體 AP 視為同一個「邏輯實體」，STA 在其中移動時，上層的 association、安全 context 與 Block Ack 狀態可以延續。

傳統 802.11r FT
掃描 → FT auth → reassoc → 重建 BA
中斷通常為數十 ms，期間可能掉包。
Wi-Fi 8 SMD
準備目標 AP → 切換 → 繼續
目標為無掉包轉換（make-before-break 概念）。
後端需求
AP 間要能同步 STA context、PN / sequence number、緩衝中的封包；backhaul 延遲與 controller 設計是關鍵。
Draft 狀態提醒：以下流程依 TGbn SFD 與 Draft 1.x 的方向整理。整體架構（SMD-ME 錨點、準備 / 執行兩階段、context 轉移）已相對穩定；但訊框名稱、欄位格式、金鑰是否在 AP MLD 間共用、DL 緩衝由誰轉送等細節仍在 comment resolution 中變動，實作時請對照最新 Draft。

8.1 架構：誰是「錨點」，誰只是「接入點」

理解 SMD 的關鍵是：把 Wi-Fi 7 MLO 的「一個 AP MLD、多條 link、一份 association」再往上推一層。在 MLO 中，STA 換 link 不用重新 association，因為 association 與金鑰綁在 AP MLD 上；在 SMD 中，association 與安全關係綁在 SMD Management Entity（SMD-ME）上，所以換 AP MLD 也不用重來。

錨點

SMD-ME

SMD 內的邏輯管理實體，可與某台 AP MLD 共置，也可放在 controller。持有 STA 的 association 身分、PMKSA / PTKSA（4-way handshake 的對端），並且是面向 DS（有線網路）的橋接點，所以 STA 換 AP 時上游 switch 不需要重新學 MAC。

接入點

Serving / Target AP MLD

實際收發空中訊框的 AP MLD。持有的是 link 層狀態：每條 link 的 AID、rate control、省電狀態、TWT、Block Ack scoreboard、該 BSS 的 group key（GTK / IGTK / BIGTK）。

終端

non-AP MLD（STA）

與 SMD-ME 建立一次 association / 金鑰後，在 SMD 內移動只需和目標 AP MLD「建立 link」並「切換資料路徑」。決定何時漫遊的主導權仍主要在 STA（AP 可用 BTM 建議）。

狀態傳統漫遊（含 11r）SMD 漫遊
Association / AID每台 AP 各自建立，漫遊要 reassociationassociation 綁 SMD-ME 不變；只在目標 AP MLD 配新 AID / link
PTK（unicast key）每次漫遊重新推導（FT 縮短但仍要交換）與 SMD-ME 協商的 PTKSA 延續（或在準備階段預先推導，依 Draft）

Block Ack 協議失效，要重新 ADDBA協議與 SN / window 一起轉移，不必重新 ADDBA

QoS / SCS / TWT 協議多半要重新協商可隨 context 轉移（目標 AP 依自身資源決定接受與否）
上游 L2 轉送表要靠 STA 送封包或 AP 送 L2 update 讓 switch 重新學習STA 的 MAC 位於 SMD-ME 之後，對 DS 不變

8.2 前置：第一次進入 SMD

  1. 發現：AP MLD 在 Beacon / Probe Response 中宣告自己屬於哪個 SMD（SMD 識別資訊），並透過 RNR / Neighbor Report 列出同一 SMD 的其他 AP MLD。
  2. 認證與 association：STA 以一般流程（SAE 或 802.1X）認證並 associate；差別在於安全關係的對端是 SMD-ME，所以 PMK / PTK 的作用範圍是整個 SMD，而不是單一 AP。
  3. 能力協商：雙方交換是否支援 SMD 漫遊，STA 取得 SMD 內可用的候選 AP MLD 清單，之後就可以直接做「準備 → 執行」，不再走 Authentication / Reassociation。

④⑤ 準備回應 收下目標 link 的參數、AID、目標 BSS 的 GTK / IGTK / BIGTK（以 PTK 加密保護），預先設定好目標 link 的硬體 / 韌體狀態。 把結果（接受 / 部分接受 / 拒絕 + 原因）回給 STA。 為 STA 配置 AID 與 link、預留佇列與 BA reorder buffer；此時還不送 DL 資料給 STA。
⑥ 執行指示 確認目標 link 品質足夠後，送出執行指示（時間點由 STA 主導；也可能約定在某個時刻或由首個目標 link 訊框觸發）。從此 UL 改送 Target。 停止排程新的 DL；把已送出但未被 ACK 的 MPDU、佇列中的封包狀態凍結。 —
⑦⑧ 資料路徑切換 RX 端保持同一個 reorder buffer / replay counter，所以從 Target 來的 MPDU 只要 SN、PN 連續就能直接交給上層。 把未送 / 未確認的 DL 封包（含 SN）交回 SMD-ME 或直接轉給 Target，以及最新的 TX PN。 SMD-ME 把 DS 方向的轉送目的地改成 Target；Target 接手 DL，從交接的 SN / PN 繼續送，並處理可能的重複封包。
⑨ 恢復傳輸 開始在目標 link 收發，沿用既有 BA 協議，不送 ADDBA；rate control 從目標 link 的量測重新收斂。 — Target 以既有 BA 協議回 BlockAck；省電、TWT 依轉移後的設定運作。
⑩ 收尾 拆除與 Current AP 的 link（或保留作為下次快速回退的候選，依實作）。 釋放 AID、佇列、BA scoreboard；短時間保留 context 以便切換失敗時回退。 SMD-ME 記錄新的 serving AP；下次漫遊從 Target 出發重複相同流程。

8.6 資料平面的細節：為什麼能做到「不掉包」

DL

下行封包不遺失

Current AP 在 ⑥ 之後不再排程新 DL；已在空中但未被 ACK 的 MPDU 與佇列內封包連同 SN 交接給 Target，由 Target 重送。STA 端 reorder buffer 不重置，所以重複收到的會被丟棄、缺的會被補上。

UL

上行封包不遺失

STA 在 ⑥ 前的 UL 走 Current；之後改送 Target。Current 已收到但尚未往 DS 送出的 UL 封包要先送完，SMD-ME 需處理 UL 亂序（兩個 AP 的 backhaul 延遲可能不同）。

安全

PN 與 replay 保護

若 PTK 在 AP MLD 間共用，同一把金鑰下 PN 絕不能重複使用：Current 必須先停止用該金鑰發送，把最後 TX PN 交給 Target 接續；RX replay counter 同理，否則會被當成重放攻擊而丟包。這是 ⑥–⑦ 要有明確順序的主因。

BA

Block Ack 與 SN 空間

每個 TID 的 SN、WinStart、buffer size 一起轉移；Target 接手後直接用既有協議聚合。若 Target 的 buffer size 能力較小，需在準備階段協商調整，避免切換後 window 不一致。

多 link

與 MLO 的結合

STA 可以在 Target 建立和 Current 不同的 link 組合（例如從 5+6 GHz 換成 2.4+6 GHz）。EMLSR STA 可利用其中一條 radio 先在目標 link 做量測與準備，縮短切換。

失敗

回退與異常

準備階段被拒：STA 仍在 Current，不受影響。執行後目標 link 失敗：Current 短暫保留的 context 讓 STA 可回退；超時則回到一般 association 流程。Target 拒絕部分協議（如 TWT）時，STA 需在切換後重新協商。

8.7 對系統設計的直接影響

  • Backhaul 延遲預算：②③④ 與 ⑦⑧ 都走 DS。準備階段可容忍較長延遲（資料不中斷），但 ⑦⑧ 直接加到中斷時間上；有線 backhaul 一般為亞毫秒級，無線 Mesh backhaul 需特別評估。
  • SMD-ME 放哪裡：放在 controller → 集中管理、容易擴展，但多一跳；與某台 AP 共置 → 延遲低，但該 AP 成為單點故障。若金鑰與加解密集中在 SMD-ME（類似企業級 tunnel 架構），AP 端就不需要同步 PN，但資料面全部經過 SMD-ME。
  • Context 格式與版本：不同廠商 / 不同韌體的 AP 混在同一 SMD 時，context 的編碼與可轉移項目必須一致；建議在韌體中把「可轉移 context」做成獨立、可序列化的資料結構。
  • STA 端：漫遊決策 policy（何時送 ① 與 ⑥）決定實際體驗；driver 要能同時維護兩組 link 狀態，並在 ⑥ 的瞬間原子性地切換 TX 路徑與金鑰 / PN 狀態。
  • 量測：漫遊 KPI 應拆成「準備耗時」與「切換中斷時間（⑥→⑨ 第一個成功 MPDU）」，並統計切換前後的 SN gap 與重複封包數。

9名詞表

UHR
Ultra High Reliability，802.11bn 的 PHY/MAC 名稱（對應 HE、EHT）。
TGbn
IEEE 802.11 負責制定 802.11bn 的 Task Group。
MAPC
Multi-AP Coordination，多 AP 協作框架。
Sharing AP
取得 TXOP 並分享給其他 AP 的發起端。
Shared AP
受邀使用 Sharing AP TXOP 資源的 AP。
Co-SR
Coordinated Spatial Reuse，以功率控制實現同時傳輸。
Co-BF
Coordinated Beamforming，以 nulling 抑制對鄰 BSS 的干擾。
Co-TDMA
Coordinated TDMA，在 TXOP 內分時給不同 AP。
Co-RTWT
Coordinated Restricted TWT，跨 AP 對齊保護低延遲時段。
NPCA
Non-Primary Channel Access，主通道忙時使用非主通道。
DSO
Dynamic Sub-band Operation，動態將窄頻 STA 分配到寬頻 BSS 的子頻帶。
DRU
Distributed Resource Unit，tone 分散於較寬頻寬的 RU，突破 PSD 限制。
UEQM
Unequal Modulation，不同 spatial stream 使用不同調變。
ELR
Enhanced Long Range，長距離 PPDU 格式。
SMD
Seamless Mobility Domain，跨 AP 無縫漫遊的邏輯網域。
SMD-ME
SMD Management Entity，SMD 的錨點：持有 STA 的 association 與 PTKSA，並作為對 DS 的橋接點。
FT
Fast BSS Transition（802.11r），以預先推導的金鑰階層縮短漫遊時的認證交換。
BTM
BSS Transition Management（802.11v），AP 建議 STA 漫遊到特定 AP。
PN
Packet Number，CCMP/GCMP 的封包編號，用於防重放；同一金鑰下不可重複。
IDC
In-Device Coexistence，裝置內多無線電共存訊令。
P-EDCA
Prioritized EDCA，針對低延遲流量的優先通道接入機制。
MLO
Multi-Link Operation（Wi-Fi 7 引入），多鏈路同時運作。
EMLSR
Enhanced Multi-Link Single Radio，多條 link 同時聆聽，收到 initial Control frame 後集中到單一 link 收發（802.11be 35.3.17）。
EMLMR
Enhanced Multi-Link Multi-Radio，多 radio 用戶端在交換期間把 TX/RX chain 集中到某 link 以提高 NSS（802.11be 35.3.18）。
MLSR
業界用語，指未開啟 EMLSR 的 single-radio non-AP MLD：一次只在一條 link 上聆聽與收發。
STR
Simultaneous Transmit and Receive，多鏈路可同時收發。
NSTR
Nonsimultaneous Transmit and Receive，一條 link 傳送時另一條 link 無法接收的 link pair。
EML OMN
EML Operating Mode Notification frame，用來啟用 / 停用 EMLSR 或 EMLMR 並更新參數。
Initial Control frame
AP 對 EMLSR 用戶端發起交換時先送的 MU-RTS / BSRP Trigger（non-HT 6/12/24 Mb/s，含 padding）。
TWT
Target Wake Time，STA 與 AP 約定喚醒時段（SP）交換資料，其餘時間 doze；分 individual 與 broadcast 兩種。
R-TWT
Restricted TWT（802.11be 35.8），為延遲敏感 TID 保留的 broadcast TWT SP；支援的 STA 必須在 SP 開始前結束 TXOP。
TWT SP
TWT Service Period，約定的喚醒交換時段。
OBSS
Overlapping BSS，鄰近重疊的其他網路。
TXOP
Transmit Opportunity，取得通道後可連續傳輸的時間。
PSD
Power Spectral Density，6 GHz 法規常以此限制發射功率。
SFD
Specification Framework Document，TG 收斂功能時的框架文件。
